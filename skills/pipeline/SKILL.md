# Скил: Оркестрация конвейера (pipeline)

## 1. Назначение и триггеры
- **Применять когда:** задача по спеке (`specs/<ID>.md`) — фича, изменение контрактов, работа с заметным Blast Radius.
- **НЕ применять:** для точечных правок ≤ 2 файлов (есть `small-fix`) и для задач без спеки (сначала написать спеку!).

## 2. Предусловия (Inputs)
- Спека `specs/<ID>.md` существует, содержит 7 разделов и проверена отдельной сессией (промпт проверки спеки — в `orchestration/README.md`).
- Ветка задачи создана от чистого дерева; роли доступны как отдельные свежие сессии (промпты в `orchestration/roles/`, шаблоны в `orchestration/templates/`).

## 3. Пошаговая процедура (Execution Steps)
### Фаза 1: QA — риск-план и красные тесты (WRITE только в docs/ и tests/)
1. По спеке создать `docs/risk-plan-<ID>.md` (шаблон `orchestration/templates/risk-plan.template.md`): матрица рисков R-1..R-N (сценарий → вероятность/влияние → имя закрывающего теста → критерий закрытия) + графа «что сознательно не проверялось».
2. Написать приёмочные тесты по контрактам спеки в `tests/`; они обязаны падать (Red) на текущем коде.
3. Анти-чит тестов: реальный клиент/БД, строгие `assert` по схеме, мок тестируемого репозитория запрещён.
### Фаза 2: Coder — реализация (WRITE только в Blast Radius спеки)
1. Реализовать по спеке и тестам QA (промпт `orchestration/roles/CODER.md`).
2. CODE_GATE (самопроверка кодера): все ворота 0 — линтер, типы, тесты, миграции. Менять тесты QA запрещено.
3. Сформировать `.ai-team/handoff-coder.md` (шаблон `orchestration/templates/handoff-coder.template.md`): Артефакты (ветка+коммит+коды проверок) / Решения / Риски («что не смотрел» + «зона внимания ревьюера»).
### Фаза 3: Reviewer — независимый аудит (SOURCE READ-ONLY, запись только в .ai-team/)
1. Свежая сессия без истории кодера (промпт `orchestration/roles/REVIEWER.md`).
2. Верификация handoff с презумпцией скептицизма: каждое утверждение сверяется с `git diff` и спекой; ассерты тестов — на фиктивность.
3. Личный прогон проверок: ruff, типы, pytest, миграции.
4. Выход — `.ai-team/handoff-reviewer.md`: `Вердикт: ACCEPT` или `Вердикт: CHANGES_REQUESTED (Итерация N из 3)` + блокеры (Локация файл:строка / Проблема / Нарушение / Требуемое исправление).
5. CHANGES_REQUESTED → назад к Фазе 2. Лимит: **3 итерации**; третья не пройдена → ESCALATE человеку (заморозка ветки, инцидентный отчёт).
### Фаза 4: Gate-панель — приёмка 2 из 3
1. Три свежие сессии-судьи (промпт `orchestration/roles/PANEL_JUDGE.md`, желательно разные модели). Каждый читает ТОЛЬКО пакет на диске: спека, риск-план, handoff-coder, handoff-reviewer, `git diff main...HEAD`.
2. Каждый судья пишет голос в `.ai-team/panel-votes/gate-{1,2,3}.json`:
   `{"task_id": "...", "seat": 1, "verdict": "READY|REWORK", "finding": "<факт с диска; при REWORK — файл и строка>", "origin": "<клиент/модель>", "inputs_sha256": {"spec": "...", "risk_plan": "..."}}`.
3. Голоса принимаются только при совпадении хэшей спеки и риск-плана у всех судей; дублирующийся seat отклоняет весь набор.
4. Кворум: ≥ 2 READY → приёмка; 0–1 → возврат Кодеру (в пределах лимита 3) или эскалация.
5. Гейт (промпт `orchestration/roles/GATE.md`) фиксирует итоговый `.ai-team/verdict.md` по 5-пунктной рубрике (`orchestration/templates/gate-rubric.md`): первая строка ровно `Вердикт: READY` / `REWORK` / `ESCALATE`.
### Фаза 5: Merge
1. `Вердикт: READY` → допуск к мержу. CI-минимум: файл `.ai-team/verdict.md` существует, первая строка READY, повторный прогон ruff/типов/тестов — 0.
2. Риск-план, handoff-файлы, голоса и вердикт коммитятся как Quality Trail.

## 4. Выходные артефакты (Outputs)
- `specs/<ID>.md`, `docs/risk-plan-<ID>.md`, тесты QA, код, `.ai-team/handoff-coder.md`, `.ai-team/handoff-reviewer.md`, `.ai-team/panel-votes/*.json`, `.ai-team/verdict.md`.

## 5. Ворота готовности (Definition of Done)
1. Все ворота проекта возвращают 0 (ruff, типы, pytest, alembic check).
2. Reviewer: `Вердикт: ACCEPT`. Панель: кворум 2 из 3 READY при совпадающих хэшах входов.
3. `.ai-team/verdict.md` первая строка: `Вердикт: READY`.

## 6. Стоп-условия и откат
- Третий возврат Кодеру не пройден — ESCALATE: заморозить ветку, составить инцидентный отчёт, решение за человеком (в т.ч. возможная правка самой спеки; после правки спеки счётчик итераций сбрасывается, а старые голоса панели аннулируются — хэши изменились).
- Изменились требования по ходу работы — сначала обновить спеку на диске, потом код (Spec Drift); пересоздание спеки/риск-плана обнуляет голоса панели.
- Хирургический фикс после ревью: только указанный дефект, без попутного рефакторинга; в handoff-coder добавляется раздел «Ответ на замечания ревьюера».
