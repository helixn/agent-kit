# Скил: open-gsd-pipeline

## Триггеры
- Задача затрагивает больше двух файлов или несколько слоёв.
- Новая доменная фича (например, Billing).
- Сессия длиннее пяти шагов, заметна потеря фокуса.

## Процедура
1. RESEARCH (`Active State: DISCUSS`): прочитать индекс и паспорт, записать требования в `.planning/REQUIREMENTS.md`.
2. PLAN: разбить работу на волны по слоям в `.planning/ROADMAP.md`; файлы волн не пересекаются, не больше трёх файлов в волне.
3. PLAN_CHECK: выполнить `python3 tools/plan_checker.py`; без кода 0 волны не начинать.
4. EXECUTE_WAVE (`Active State: EXECUTE`): одна волна, одна сессия, чистое окно; вход только `STATE.md`, свой пункт `ROADMAP.md` и файлы предыдущей волны на чтение.
5. VERIFY: слои, бюджет, тесты; не больше трёх попыток исправления.
6. COMMIT (`Active State: DONE`): отметить волну в `ROADMAP.md` и записать Structured Handoff в `STATE.md`.

## Ворота готовности
- [ ] Три файла `.planning/` на месте, `plan_checker.py` возвращает 0.
- [ ] Каждая волна отмечена `[x]`, Handoff не длиннее 15 строк.

## Стоп-условия
- Счётчик попыток превысил лимит: вернуться в PLAN, подготовить откат файлов волны (выполняет человек).
- Волна пытается менять файлы другой волны: остановить и переразбить.
