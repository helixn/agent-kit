# Скил: Послойная разработка фичи (fastapi-feature)

## 1. Назначение и триггеры
- **Применять когда:** нужно добавить эндпоинт, поле или бизнес-правило в существующий сервис.
- **НЕ применять:** для чистого рефакторинга (есть `safe-refactoring`) и для изменения схемы БД без новой логики (есть `database-migration`).

## 2. Предусловия (Inputs)
- `uv run pytest tests/characterization/ -q` зелёный.
- Если нужна новая таблица/колонка — миграция уже создана скилом `database-migration`.
- Зона влияния правок из `architecture-map.md` (3–6 файлов).

## 3. Пошаговая процедура (Execution Steps)
### Фаза 1: Проверка защитного слепка
1. Убедиться, что слепок старых эндпоинтов зелёный до начала работ.
### Фаза 2: Контракты и DTO
1. Описать входные/выходные модели в слое схем с `ConfigDict(from_attributes=True)`.
2. Новые поля в ответах — только обратно совместимо: опциональные, со значением по умолчанию.
### Фаза 3: Красный тест
1. Написать модульный и интеграционный тесты на новую фичу.
2. Запустить `uv run pytest`: новый тест обязан падать ПО ОЖИДАЕМОЙ ПРИЧИНЕ (404/несуществующий эндпоинт), а не из-за опечатки в импорте. Проверять текст ошибки, а не только факт красного.
### Фаза 4: Реализация строго снизу вверх
1. Репозиторий — асинхронные запросы, только `flush()`.
2. Сервис — бизнес-логика, доменные исключения, владение транзакцией.
3. Роутер — тонкий обработчик: принимает схему, вызывает сервис, мапит доменные исключения в HTTP-статусы.
### Фаза 5: Верификация и правило «только вверх»
1. Прогнать все наборы тестов; слепок `tests/characterization/` не сломан.
2. Поднять `fail_under` (например, 80 → 85) — только после зелёного результата.

## 4. Выходные артефакты (Outputs)
- Код слоёв в `app/schemas/`, `app/repositories/`, `app/services/`, `app/api/` и тесты в `tests/`.

## 5. Ворота готовности (Definition of Done)
1. `uv run ruff check .`, `uv run ruff format --check .`, `uv run basedpyright` возвращают 0.
2. `uv run pytest -q --cov=app --cov-branch --cov-fail-under=<новый порог>` возвращает 0.
3. Старые ответы существующих эндпоинтов не изменились ни на один ключ (проверка слепком).

## 6. Стоп-условия и откат
- Если для фичи требуется изменить формат ответа старого эндпоинта — немедленный стоп и отчёт человеку.
- После 3 попыток падает `tests/characterization/` — немедленный стоп: `git restore --staged --worktree -- app alembic tests`, удалить сгенерированные неотслеживаемые файлы ревизий, отчёт.
- Запрещено писать SQL в роутере и ослаблять существующие тесты.
