# Скил: Защитный слепок поведения сервиса до правок (characterization-tests)

## 1. Назначение и триггеры
- **Применять когда:** в существующем проекте нужно что-то менять, а текущее поведение критических маршрутов ещё не зафиксировано тестами.
- **НЕ применять:** для нового кода по TDD и когда слепок уже снят и зелёный.

## 2. Предусловия (Inputs)
- Есть `architecture-map.md` (результат `investigate-codebase`).
- БД проекта запущена, миграции накатаны.
- `git diff --exit-code app/` возвращает 0 (код приложения не тронут).

## 3. Пошаговая процедура (Execution Steps)
### Фаза 1: Матрица сценариев
1. Выписать критические маршруты из `architecture-map.md`: создание (201), чтение/редирект (200/307/404), статистика/статус, блокировка опасного ввода (422).
2. Для каждого сценария зафиксировать вход, статус-код, заголовки и точные ключи JSON.
### Фаза 2: Тесты фиксации
1. Создать `tests/characterization/test_critical_path.py`.
2. Каждый тест проверяет ФАКТИЧЕСКИЙ ответ системы, даже если он выглядит странно; ожидания выводятся наблюдением, а не требованиями.
3. Неожиданный статус — зафиксировать именно его, а не «правильный». Найденные баги — в отчёт человеку отдельной задачей, не чинить сейчас.
### Фаза 3: Запуск и порог покрытия
1. `uv run pytest tests/characterization/ -q`: все тесты зелёные на нетронутом коде.
2. Поднять `fail_under` в `pyproject.toml` (правило «только вверх»; базовая ступень — 60).

## 4. Выходные артефакты (Outputs)
- `tests/characterization/test_critical_path.py`.
- Поднятый `fail_under` в `pyproject.toml`.

## 5. Ворота готовности (Definition of Done)
1. `git diff --exit-code app/` возвращает 0.
2. `uv run pytest tests/characterization/ -q --cov=app --cov-branch --cov-fail-under=<текущий порог>` возвращает 0.
3. `uv run ruff check tests/` и `uv run basedpyright tests/` возвращают 0.

## 6. Стоп-условия и откат
- Запрещено изменять любые файлы в исходниках и миграциях.
- Если `git diff` по исходникам не пуст — немедленно `git restore` и прекратить работу.
- Тест зелёным не становится после 3 попыток — остановиться и доложить человеку, НЕ «чиня» сервис.
