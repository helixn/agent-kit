# agent-kit — переносимый инженерный харнес для автономных AI-агентов

Дистрибутив методологии из ранбуков «От вайб-кодинга к профессиональной AI-разработке»
(**День 1**: правила, скилы, харнес; **День 2**: оркестрация — конвейер кодера, ревьюера и панели техлидов).

Формула контура: **нерушимые правила (`AGENTS.md`) + процедурные скилы (`SKILL.md`) + машинные ворота
качества (ruff / basedpyright / pytest / alembic) + ролевой конвейер приёмки (Coder → Reviewer → Gate-панель 2 из 3)**.
Комплект превращает «вайб-кодинг» в управляемую разработку в любом Python-проекте за одну установку.

## Куда ставить

Установщик разворачивает контур **внутрь целевого проекта**. Целевая директория — **корень проекта/сервиса**,
тот каталог, где лежит (или будет лежать) `pyproject.toml`. Сам комплект agent-kit клонируется в любое место
хранения (например, `~/tools/agent-kit`) и в проект не копируется целиком — только через установщик.

Структура внутри целевого проекта после установки:

| Путь в проекте | Что появляется |
|---|---|
| `.agents/skills/<имя>/SKILL.md` | 9+ процедурных скилов (+ скилы направления) |
| `.agents/AGENTS.md` | Канон правил (шаблон с `{{PLACEHOLDER}}`) |
| `AGENTS.md`, `CLAUDE.md` | Входы для агентов (копия канона / `@AGENTS.md`) |
| `ONBOARDING-AGENT.md` | Контракт автономного агента: порядок работы, стоп-условия, BLOCKED |
| `orchestration/` | Роли конвейера, шаблоны артефактов, рубрика гейта, изоляция прав |
| `docs/architecture-map.template.md`, `docs/gates.pyproject.toml` | Шаблон карты архитектуры, ворота качества |
| `specs/`, `docs/`, `.ai-team/` | Спеки, риск-планы, handoff-пакеты и вердикты конвейера |

## Как ставить (3 шага)

```bash
# 1. Забрать комплект (в любое место хранения):
git clone https://github.com/helixn/agent-kit.git ~/tools/agent-kit

# 2. Из КОРНЯ целевого проекта запустить установщик с направлением:
cd /path/to/your-project
bash ~/tools/agent-kit/INSTALL/install.sh . web-fastapi     # или quant-ml; без 2-го аргумента — универсальный слой
#   PowerShell-вариант:
#   ~/tools/agent-kit/INSTALL/install.ps1 -Target . -Direction web-fastapi

# 3. Довести до боя:
#    - заполнить {{PLACEHOLDER}} в .agents/AGENTS.md и продублировать в корневой AGENTS.md;
#    - перенести секции из docs/gates.pyproject.toml в pyproject.toml (без дублей таблиц TOML);
#    - первый запуск агента: «Прочитай ONBOARDING-AGENT.md, затем выполни скил investigate-codebase».
```

Установщик идемпотентен: повторный запуск перезаписывает файлы комплекта теми же версиями, ничего не удаляя.

## Состав комплекта

| Путь | Назначение |
|---|---|
| `ONBOARDING-AGENT.md` | Точка входа любого автономного агента |
| `INSTALL/` | Установщики: `install.sh` (Git Bash/Linux) и `install.ps1` (Windows PowerShell) |
| `common/` | Универсальный слой: конституция, ворота качества, карта архитектуры |
| `skills/` | 9 процедурных скилов в формате открытого стандарта Agent Skills |
| `orchestration/` | Ролевой конвейер: промпты ролей, шаблоны, рубрика, изоляция, валидатор handoff |
| `directions/` | Пакеты направлений: `web-fastapi`, `quant-ml` + как собрать своё |

## Маршрутизатор задач

| Задача звучит как | Скил |
|---|---|
| «исследуй / с чего начать / что сломаю» | `investigate-codebase` |
| «зафиксируй текущее поведение до правок» | `characterization-tests` |
| «покрой бизнес-логику тестами» | `tests-unit` |
| «проверь сквозной путь с реальной БД» | `tests-integration` |
| «изменилась модель / схема БД» | `database-migration` |
| «добавь фичу / эндпоинт / поле» | `fastapi-feature` (схема нужна — сначала `database-migration`) |
| «причеши / отрефактори» | `safe-refactoring` |
| «мелкая правка в 1–2 файлах» | `small-fix` |
| «фича по спеке, под контролем» | `pipeline` |

Правило размера: правка > 2 файлов — не `small-fix`. Фича и рефакторинг никогда не в одном коммите.

## Конвейер оркестрации (кратко)

Спека (`specs/<ID>.md`, 7 разделов) → **QA**: риск-план + красные тесты → **Coder**: реализация в Blast Radius →
CODE_GATE (ворота 0) → **Reviewer** (свежая read-only сессия) → до 3 итераций → **Gate-панель** (3 судьи,
кворум 2/3, голоса по хэшам входов) → `Вердикт: READY` → merge. Всё состояние на диске (`specs/`, `docs/`,
`.ai-team/`), передача между ролями — сжатые handoff-файлы (1–3 КБ), не копия диалога.

## Ворота по умолчанию

`ruff check` → `basedpyright` → `pytest --cov-branch` (порог — только вверх) → `alembic check` (если есть миграции).
**Зелёный pytest ≠ сдача**: для задач по спеке приёмка только через `orchestration/templates/gate-rubric.md`.

## Направления

- **web-fastapi** — HTTP-сервисы FastAPI/SQLAlchemy/Alembic: правила слоёв, обратная совместимость API, timestamptz.
- **quant-ml** — квант/ML-исследования: скилы `experiment-protocol` (заморозка протокола до fit, one-shot,
  потреблённые периоды) и `data-causal` (агрегации по закрытым барам, asof-join, метки без заглядывания).
- Своё направление — см. `directions/README.md`.

## Происхождение

Принцип Zero Hidden Scripts:
всё, на что ссылаются скилы, лежит в комплекте; внешние инструменты помечены как опциональные.
Скилы читаются OpenCode / Cursor / Copilot / Codex / Claude Code (для последнего — `CLAUDE.md` с `@AGENTS.md`).
