# Оркестрация: ролевой конвейер (Coder → Reviewer → Gate-панель)

## Почему роли разделены
Одна сессия не может ревьюить сама себя: предвзятость подтверждения, ловушка зеркала (Mirror Test Trap),
поддакивание (sycophancy) и гниение контекста (Lost in the Middle). Надёжность даёт только физическое
разделение ролей с передачей сжатых пакетов на диске (Structured Handoff, 1–3 КБ), а не копией диалога.

## Роли и права

| Роль | Промпт | Права записи | Выход |
|---|---|---|---|
| QA | `roles/QA.md` | только `docs/` и `tests/` | `docs/risk-plan-<ID>.md` + красные тесты |
| Coder | `roles/CODER.md` | только Blast Radius спеки (`app/`) | код + `.ai-team/handoff-coder.md` |
| Reviewer | `roles/REVIEWER.md` | SOURCE READ-ONLY; запись только `.ai-team/handoff-reviewer.md` | ACCEPT / CHANGES_REQUESTED |
| Techlead Gate | `roles/GATE.md` | SOURCE READ-ONLY; запись только `.ai-team/verdict.md` | READY / REWORK / ESCALATE |
| Судья панели | `roles/PANEL_JUDGE.md` | запись только `.ai-team/panel-votes/gate-<N>.json` | голос READY/REWORK |

## Как запускать роль

Каждая роль — **отдельная свежая сессия** (CLI-запуск без истории или чистая вкладка IDE):

```bash
cd <проект>
opencode run "$(cat orchestration/roles/REVIEWER.md)

Задача: <ID>, спека: specs/<ID>.md. Выполни аудит согласно своей роли." < /dev/null
```

Изоляция прав ревьюящих ролей: `isolation/opencode.json.example` (запрет `edit` везде, кроме `.ai-team/**`).
В Cursor/Claude Code — чистая сессия на роль + жёсткий заголовок из промпта + визуальный контроль отсутствия Apply.

## Протокол передачи (Structured Handoff)

Передаётся НЕ диалог, а файл фиксированной структуры (шаблоны в `templates/`):
- `handoff-coder.template.md` — Артефакты / Решения / Риски («что не смотрел», «зона внимания ревьюера»).
- `handoff-reviewer.template.md` — вердикт первой строкой + блокеры (файл:строка / проблема / нарушение / фикс).
- `verdict.template.md` — итог по 5-пунктной рубрике `templates/gate-rubric.md`.
- `risk-plan.template.md` — матрица рисков до кода.

Чек-лист валидности handoff: точные хэши/ветки; числовые коды проверок; координаты файл:строка;
честная граница рисков; объём 1–3 КБ (~400–1200 токенов); машиночитаемый статус первой строкой.
Невалидный пакет отклоняется без анализа. Опционально — `scripts/validate_handoff.py`.

## Лимиты и эскалация

- Ревью-цикл: **N ≤ 3**. Круг 1 — первичное ревью; круг 2 — финальный шанс; круг 3 не пройден → ESCALATE
  (заморозка ветки, инцидентный отчёт, решение человека; после правки спеки счётчик сбрасывается, старые голоса аннулируются).
- Приёмка: панель 3 судей, кворум **2 из 3**, голоса привязаны к хэшам спеки и риск-плана.
- Хирургический фикс после ревью: только указанный дефект; ответ ревьюеру — в handoff-coder.

## Быстрая проверка спеки (до конвейера)

```bash
opencode run "Ты ревьюер спецификации. Прочитай specs/<ID>.md и проверь: 1) все 7 разделов; 2) разрешённые и запрещённые файлы; 3) код ответа при ошибке для каждого эндпоинта; 4) у каждого пункта DoD команда с кодом выхода. Файлы не меняй. Выведи таблицу: пункт, ОК/дефект, цитата." < /dev/null
```
