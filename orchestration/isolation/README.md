# Изоляция прав ревьюящих ролей (Reviewer / Gate / Судья)

Цель: проверяющие роли физически не могут изменить исходники проекта.

1. **OpenCode** — гранулированное правило `permission` в `opencode.json` (см. `opencode.json.example`):
   `edit` запрещён везде, кроме каталога `.ai-team/**`. ВАЖНО: конфиг гарантирует доступ только к КАТАЛОГУ
   — «каждая роль пишет только свой файл» (handoff-reviewer.md / verdict.md / gate-<N>.json) обеспечивается
   дисциплиной промпта роли, а не этим правилом.
2. **Лазейка через shell:** при `"bash": "allow"` теоретически возможна правка файлов утилитами
   (`sed -i`, `>`). Для абсолютной изоляции в CI: `chmod -R a-w app/ tests/ alembic/` на время работы
   read-only сессии (снять после) либо режим подтверждения консольных команд.
3. **Cursor / Claude Code** — изоляция контекстная: чистая сессия на роль + жёсткий заголовок из промпта
   роли + человек визуально контролирует отсутствие Apply/диффов. В Claude Code в CI —
   `permissions.deny` на файловые модификации.
4. Кодеру изоляция НЕ ставится — это единственная роль с правом записи в исходники (в пределах Blast Radius).
