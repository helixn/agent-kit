# ONBOARDING — контракт автономного агента (прочти ПЕРВЫМ)

Ты автономный агент в проекте, где установлен agent-kit. Ниже — нерушимый порядок работы.
Он не зависит от твоей модели, версии клиента и формулировки задачи.

## 0. Приоритет источников правды

1. Исполняемый код, действующие миграции, автоматические проверки (pytest / ruff / тайпчекер).
2. `AGENTS.md` (закон репозитория) и контракт активного скила `SKILL.md`.
3. `architecture-map.md` (навигационная карта; быстро устаревает).
4. История текущего чата — самый низкий приоритет.

При расхождении — верь коду и сообщи о расхождении. Не «вспоминай» правила из прошлых сессий: читай файлы с диска.

## 1. Первое действие в незнакомом коде — только чтение

До первой правки запусти скил `investigate-codebase` и получи `architecture-map.md` с зоной влияния правок (Blast Radius).
`git status` по исходникам обязан остаться чистым: в такте разведки разрешено создать только файл карты.

## 2. Маршрутизация задачи

| Задача | Скил |
|---|---|
| новая задача по существующему коду | `investigate-codebase` (сначала всегда) |
| зафиксировать поведение до правок | `characterization-tests` |
| покрыть доменную логику | `tests-unit` |
| сквозной путь с БД | `tests-integration` |
| изменение схемы | `database-migration` |
| новая функциональность | `fastapi-feature` |
| изменение структуры без поведения | `safe-refactoring` |
| точечная правка ≤ 2 файлов | `small-fix` |
| фича по спеке / большой объём | `pipeline` |

Смешанные задачи разбиваются на несколько запусков. Фича и рефакторинг никогда не в одном коммите.

## 3. Definition of Done (ворота готовности)

Задача не завершена, пока все команды подряд не вернули код возврата `0`:

1. `uv run ruff check app tests`
2. `uv run basedpyright` (или тайпчекер проекта)
3. `uv run pytest -q --cov-branch` (порог покрытия в `pyproject.toml`; правило «только вверх»)
4. `uv run alembic upgrade head && uv run alembic check` (если в проекте есть миграции)

Для задач по спеке приёмка — только через рубрику `orchestration/templates/gate-rubric.md`.
**Зелёный pytest ≠ сдача.**

## 4. Категорические запреты (Anti-Cheat)

- ослаблять, комментировать или удалять существующие `assert`; ставить `pytest.mark.skip`;
- добавлять `# noqa`, `# type: ignore`, `# pyright: ignore` без письменного разрешения техлида;
- глушить исключения (`except Exception: pass`);
- снижать `fail_under` и любые пороги ворот;
- менять тесты, чтобы прошёл баг: чинится реализация, тест — оракул;
- менять БД в обход миграций (psql/DDL руками);
- выводить токены/секреты/PII в логи (Zero Auth Leak, CWE-532);
- выполнять мутирующие SQL-запросы через read-only MCP-инструменты инспекции;
- авто-merge веток без явного вердикта гейта (Human-in-the-Loop).

Коммиты: префикс `[agent]` (автономный), `[assisted]` (с правкой человека), `[manual]` (человек).

## 5. Стоп-условия и откат

- одни и те же ворота красные **3 попытки подряд** → остановиться (четвёртой попытки нет);
- изменён файл вне Blast Radius → немедленно `git restore <файл>` и стоп;
- **запрещено** `git clean -fd` — он стирает в том числе чужую работу;
- после 2 неудач с ошибкой окружения (БД/сеть/пути) — стоп: причина не в коде.

Протокол отката:
```bash
git status --short && git diff --stat          # зафиксировать состояние
mkdir -p .bak && git diff > .bak/blocked-$(date +%Y%m%d-%H%M).patch   # сохранить улики
git restore --staged --worktree -- <пути зоны влияния>                # откат только своей зоны
rm -f <по явному списку созданных тобой файлов>                       # без clean
git status --short                              # убедиться в чистоте
```

## 6. Отчёт BLOCKED (заголовок `BLOCKED:` + ровно 6 полей)

```
BLOCKED: <скил>, <задача>
Гипотеза: <почему не выходит>
Факт сбоя: <ворота/команда> не прошли N раз подряд. Последняя ошибка: <текст>
Причина остановки: <пункт стоп-условий скила / лимит 3>
Состояние до отката: <git status --short>
Состояние после отката: <пусто, кроме .bak/>. Патч: <путь>
Что нужно от человека: <один конкретный вопрос>
```
После BLOCKED не делать ничего без новых указаний человека.

## 7. Оркестрация (задачи по спеке)

Скил `pipeline`. Каждая роль — **отдельная свежая сессия** (не один чат):
системные промпты — `orchestration/roles/`, шаблоны артефактов — `orchestration/templates/`.
Reviewer и Gate — строго read-only по исходникам; запись разрешена только в `.ai-team/`
(изоляция: `orchestration/isolation/opencode.json.example`). Лимит итераций 3 → эскалация человеку.
Handoff между ролями — сжатые файлы на диске (1–3 КБ), никогда — копия диалога.
