## 1. Контекст и навигация

## 2. Нерушимые правила архитектуры и границ слоёв
1. **Транспортный слой ({{app/api/}}):** только приём HTTP-запроса, валидация схемой, вызов сервиса.
   - СТРОГИЙ ЗАПРЕТ: импорты слоя данных/ORM и SQL/сессии БД внутри обработчиков.
2. **Сервисный слой ({{app/services/}}):** вся бизнес-логика, доменные исключения, владение транзакцией.
   - СТРОГИЙ ЗАПРЕТ: импортировать HTTP-объекты (Request/Response/HTTPException) — коды ответа мапит роутер.
3. **Слой данных ({{app/repositories/, app/models/}}):** единственная точка доступа к БД; `flush()` — здесь, `commit()`/`rollback()` — сервис или жизненный цикл запроса.
4. **Защита внешних контрактов:** СТРОГИЙ ЗАПРЕТ переименовывать/удалять существующие поля ответов, менять статус-коды и формат ошибок. Новые поля — только опциональные со значением по умолчанию (обратная совместимость).
5. Все входные данные из HTTP — только через схемы {{Pydantic}}; нетипизированный `request.json()` запрещён.

## 3. Данные и миграции
1. Любое изменение моделей сопровождается миграцией {{Alembic}}. `create_all()` в рантайме приложения запрещён.
2. Каждая миграция обязана иметь полный `downgrade()` (никаких пустых `pass`).
3. Перед сдачей — маятник: `upgrade head` → `downgrade -1` → `upgrade head` → `check` (все с кодом 0).

## 4. Строгие запреты против обхода проверок (Anti-Cheat) и безопасность
КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:
- ослаблять/удалять/комментировать существующие проверки и тесты; `pytest.mark.skip`;
- `# noqa` / `# type: ignore` / `# pyright: ignore` без письменного разрешения техлида;
- глушить исключения (`except Exception: pass`);
- снижать `fail_under` и любые пороги (правило «только вверх»: повышать можно, понижать — нет);
- менять рабочий код до снятия защитного слепка (characterization-тесты);
- логировать токены, секреты, персональные данные (Zero Auth Leak, CWE-532);
- выполнять мутирующие запросы (INSERT/UPDATE/DELETE/DDL) через read-only MCP-инструменты инспекции;
- автоматически вливать ветки/PR без явного вердикта гейта (Human-in-the-Loop).
Коммиты обязаны иметь префикс `[agent]` / `[assisted]` / `[manual]` (аудит происхождения).

## 5. Ворота готовности (Definition of Done)
Ни одна задача не считается выполненной, пока все команды подряд не вернули код 0:
1. `uv run ruff check app tests`
2. `uv run basedpyright`
3. `uv run pytest -q` (покрытие: `--cov-branch`, порог в `pyproject.toml`)
4. `uv run alembic upgrade head && uv run alembic check` (если есть миграции)

## 6. Использование процедурных скилов
1. Для каждой задачи найди скил в `.agents/skills/` и выполняй его фазы строго по порядку.
2. Не завершай работу, пока не закрыт Definition of Done активированного скила.
3. Сработало стоп-условие скила — остановись, откатись и доложи человеку (формат BLOCKED — в `ONBOARDING-AGENT.md`), а не обходи запрет.
